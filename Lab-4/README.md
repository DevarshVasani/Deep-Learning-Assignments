# Lab 4: Object Detection on Fruit Dataset

## Overview
This lab demonstrates the evolution of object detection techniques, starting from fundamental concepts like Intersection over Union (IoU) and progressing through classic R-CNN architectures to modern real-time detectors. The project applies these techniques to detect apples, bananas, and oranges within a Pascal VOC formatted fruit dataset.

---

## Task-by-Task Implementation Guide

### Task 1: Intersection over Union (IoU)

**Objective:** Implement the fundamental metric for evaluating object detection predictions.

**How It's Achieved:**
- Calculate the intersection area between two bounding boxes by finding the overlapping region
- Calculate the union area by summing both box areas and subtracting the intersection
- Compute the ratio: intersection area ÷ union area
- This metric ranges from 0 (no overlap) to 1 (perfect overlap) and measures how well predicted boxes align with ground truth

**Application:** IoU is used throughout the pipeline to match predictions against ground truth labels and to suppress duplicate detections.

---

### Task 2: Selective Search (Region Proposal Generation)

**Objective:** Generate candidate bounding box proposals that likely contain objects of interest.

**How It's Achieved:**
- Start with an image segmentation algorithm that groups similar pixels into regions
- Iteratively merge neighboring regions based on similarity metrics (color, texture, size, fill)
- After each merge, generate rectangular bounding boxes that enclose the resulting regions
- Collect hundreds of region proposals at different scales and aspect ratios
- Filter to keep the most promising proposals (top 200 in this task)

**Application:** These proposals serve as candidates for detailed analysis in the R-CNN pipeline, reducing the search space from all possible bounding boxes to a manageable set.

---

### Task 3: R-CNN Bottleneck Simulation (Per-Proposal Analysis)

**Objective:** Demonstrate the computational challenge in the original R-CNN approach.

**How It's Achieved:**
- Extract each region proposal from the image
- Resize each proposal to a fixed size
- Pass each proposal independently through a deep convolutional network to extract visual features
- Collect feature vectors for all proposals
- Measure the total processing time

**Key Insight:** The bottleneck occurs because:
- Many region proposals overlap significantly
- Each overlapping region is processed independently through multiple convolutional layers
- Identical or near-identical convolutions are computed repeatedly for overlapping regions
- This results in massive computational redundancy

**Performance Impact:** Processing 100 proposals takes several seconds due to repeated deep convolutions on overlapping image regions.

---

### Task 4: Fast R-CNN (Feature Map Sharing with RoI Pooling)

**Objective:** Eliminate redundant computations by sharing convolutional features.

**How It's Achieved:**
1. **Single Feature Extraction:** Process the entire image through convolutional layers once to generate a feature map
2. **Spatial Mapping:** Calculate how positions in the original image correspond to positions in the feature map
3. **RoI Pooling:** For each region proposal:
   - Map the proposal's coordinates to the feature map using the spatial scale
   - Extract the corresponding feature region from the feature map
   - Apply pooling to produce a fixed-size feature vector
4. **Efficiency Gain:** All proposals are processed from the shared feature map rather than independently

**Key Optimization:** 
- Convolutional computation (which is expensive) happens only once
- Region-specific extraction (which is cheap) happens for each proposal
- The speedup is substantial: ~10-50x faster than R-CNN

**Performance Improvement:** Processing 100 proposals now takes only milliseconds instead of seconds.

---

### Task 5: Faster R-CNN (End-to-End Region Proposal Network)

**Objective:** Make region proposal generation learnable and integrate it with detection.

**How It's Achieved:**
1. **Feature Pyramid Creation:** Generate convolutional features from the entire image
2. **Region Proposal Network (RPN):**
   - At each position in the feature map, predict whether objects are likely present
   - Generate multiple proposal boxes of different sizes and aspect ratios (anchors)
   - Predict offsets to refine anchor positions
   - Output objectness scores for each proposal
3. **Proposal Filtering:** Eliminate low-confidence proposals and overlapping duplicates
4. **RoI Pooling & Detection:** Process remaining proposals to classify objects and refine boxes
5. **Confidence Filtering:** Apply score thresholds to keep only strong detections

**Key Advancement:** 
- Proposals are generated by a trainable network instead of hand-crafted algorithms
- RPN shares convolutional features with the detection network
- The entire pipeline is end-to-end differentiable

**Result:** A single forward pass produces both proposals and detections with high accuracy.

---

### Task 6: Custom Non-Maximum Suppression (NMS)

**Objective:** Eliminate duplicate detections and keep the best prediction for each object.

**How It's Achieved:**
1. **Score Sorting:** Sort all detections by confidence score in descending order
2. **Greedy Selection:** 
   - Start with the highest-confidence detection and mark it as "keep"
   - Compare this detection against all remaining detections
   - For each comparison, calculate IoU using bounding box coordinates
   - If IoU exceeds a threshold, the lower-scoring detection is a duplicate and removed
   - Repeat with the next highest-confidence remaining detection
3. **Threshold Tuning:** The IoU threshold controls suppression strength:
   - High threshold (0.9): Weak suppression, keeps many overlapping boxes
   - Low threshold (0.1): Aggressive suppression, removes nearby boxes
   - Medium threshold (0.4-0.6): Balanced approach for crowded scenes

**Application:** NMS is essential in dense scenes (fruit clusters) where multiple detections can overlap around the same object.

### Task 7: YOLOv8 Fine-Tuning

**Objective:** Adapt a general-purpose detector to the specific fruit detection domain.

**How It's Achieved:**

**Dataset Preparation:**
- Convert ground truth annotations from one format to the YOLO format
- Split data into training, validation, and test sets (70-15-15 split)
- Organize images and labels into the required directory structure
- Create a configuration file specifying class names and dataset paths

**Fine-Tuning Process:**
1. **Load Pre-trained Model:** Start with a model already trained on large-scale object detection data
2. **Transfer Learning:** The model's learned features (from general objects) transfer to fruit detection
3. **Training Loop:**
   - Present batches of fruit images to the model
   - Compare predictions against ground truth annotations
   - Calculate loss based on class predictions and bounding box accuracy
   - Update model weights to minimize loss
   - Validate on held-out validation set
4. **Early Stopping:** Monitor validation metrics and retain the best performing weights
5. **Evaluation:** Test on unseen test set and compute standard metrics

**Key Benefits:**
- Reduces training time and data requirements compared to training from scratch
- Leverages knowledge from millions of general object images
- Achieves high accuracy with only a small fruit-specific dataset
